核心问题速查

问题 当前答案 关键证据
1. 这个 Agent 项目解决什么问题？ 面向编程教学，把普通在线判题平台增强为多 Agent 教学系统：学生获得答疑、代码审查和学习分析，教师获得 AI 出题、草稿审核和知识库管理。 README.md、app/agents/agents/
2. 用户输入从哪里进入系统？ Web 页面和外部调用都进入 Flask API，主要是 /api/v1/ai/chat、/chat/stream、/review、/generate*。 app/web/ai_chat.py、app/api/v1/ai.py
3. Agent 主流程怎么执行？ 认证限流、加载会话、构造 AgentState、LangGraph 路由、组装 Prompt、调用 LLM、执行工具、处理 handoff/校验、保存消息和 trace。 chat()、chat_stream()、AgentOrchestrator
4. Agent 是否有任务规划能力？ 有流程编排和条件分支，但不是完整通用 Planner-Executor。已实现 auto route、handoff、结构校验重试、生成题目的 LangGraph pipeline；agent_tasks.plan_steps 支持任务步骤字段。 orchestrator.py、generation_pipeline.py、agent_task.py
5. Agent 如何调用 LLM？ 统一由 AIConfig.get_llm() 创建 OpenAI-compatible ChatOpenAI，base URL 指向 DeepSeek，支持 invoke 和 stream，LLM 调用带重试包装。 app/agents/config.py、BaseAgent._llm_invoke
6. Prompt 在哪里？控制什么行为？ Prompt 在 app/agents/prompts/，控制角色职责、工具使用规则、输出格式、handoff 条件、安全约束和是否必须查询真实数据。 prompts/tutor.py、prompts/generator.py
7. Agent 能调用哪些工具？ 可执行代码、查询题目、查询提交、查询学生统计、查询班级统计、检索知识点、检索错误模式、检索相似题。 app/agents/tools/、TOOL_PERMISSIONS
8. 工具调用链路是什么？ LLM 通过 bind_tools 选择工具，BaseAgent 校验权限并覆盖敏感参数，调用 tool.invoke，结果作为 ToolMessage 回到消息列表，trace 记录工具步骤。 BaseAgent._run_tools()、TraceCollector
9. 是否接入 RAG 知识库？ 已接入。ChromaDB 存题目、知识点、错误模式；Tutor 构造 Prompt 时检索知识和错误模式，Generator 检索相似题，pipeline 做 dedup。 knowledge_base.py、knowledge_tools.py
10. 是否接入 MCP Client / Server？ 当前源码未实现 MCP Client 或 MCP Server。已有中文方案文档规划未来 FastAPI Agent Host 和只读 MCP Server。 docs/FASTAPI_AGENT_HOST_MCP_WORKFLOW_PLAN_ZH.md
11. 是否有 Memory / State / Session？ 有。State 用 AgentState，Session/历史用 AIConversation 和 AIMessage，长期画像用 StudentProfile 和 TeacherPreference。 state.py、memory.py、ai_conversation.py
12. 数据存在哪里？ MySQL 存用户、业务、会话、消息、trace、任务、草稿、画像、eval；ChromaDB 存向量；Redis 存限流和异步事件；日志输出到应用日志。 app/models/、data/knowledge_base、compose.yaml
13. API 怎么暴露给前端或外部系统？ Flask Blueprint 暴露 REST 和 SSE，Swagger UI 可查看 API；前端 JS 直接 fetch /api/v1/ai/*。 app/api/v1/ai.py、app/static/js/ai_chat.js
14. 日志、监控、评估怎么做？ TraceCollector 记录 LLM/tool 延迟、token、错误；教师端 traces UI 查看；eval runner 运行 JSON case suite 并持久化结果。 tracing.py、traces.js、evals/runner.py
15. 项目如何配置、启动和部署？ Docker Compose 启动 Flask、MySQL、Redis，Web 端口默认 9900；依赖在 requirements.txt 和 package.json；健康检查是 /health。 compose.yaml、docker/Dockerfile、docs/INSTALLATION.md
16. 相比普通 Chatbot 强在哪里？ 它不是只把用户消息转给模型，而是有多 Agent 分工、工具权限、真实业务数据查询、RAG、沙箱执行、可追踪运行记录、教师审核流和 eval。 orchestrator.py、tools/、generated_question_draft.py
17. 简历上应该怎么包装它？ 可定位为“面向编程教育的多 Agent 智能评测平台”，关键词是 LangGraph、Tool Calling、RAG、Agent Trace、Eval、权限隔离、AI 出题与代码审查。 见本页 ResumeValue 节点

Agent 主流程

1. 前端/API 发起请求

携带 message、agent_type、题目/提交/语言等上下文。

2. 认证与限流

require_auth 校验用户，Redis 做每用户每 Agent 的分钟级限流。

3. 会话装载

创建或复用 AIConversation，读取历史 AIMessage。

4. 路由 Agent

AgentOrchestrator 自动分类或使用显式类型。

5. 组装 Prompt

系统提示、上下文、记忆、RAG 结果、安全规则共同进入消息列表。

6. LLM + Tool Loop

LLM 可发起工具调用；服务端校验权限、注入可信参数、执行工具。

7. Handoff / 校验

需要时交给其他 Agent；reviewer/generator/analytics 可做结构校验重试。

8. 输出、追踪、持久化

返回 JSON 或 SSE，同时保存消息、trace、草稿或 eval 结果。

系统架构图

客户端层

Jinja 页面 + Vanilla JS + 外部 API 调用者

app/static/js/ai_chat.js、embedded_tutor.js、review queue 与 traces 页面通过 /api/v1/ai/* 调用 Agent 能力。

API 层

Flask Blueprint app/api/v1/ai.py

负责认证、限流、输入清洗、会话持久化、同步/流式/异步任务、题目草稿审阅、知识库管理、trace 查询和 eval 运行。

Agent 层

LangGraph + BaseAgent + 专用 Agent

orchestrator.py 负责路由与 handoff，BaseAgent 负责 LLM/tool 循环，四类 Agent 各自注入 Prompt、工具和上下文。

工具层

LangChain tools + 权限矩阵

工具包括代码执行、题目查询、提交查询、统计查询、知识库检索。TOOL_PERMISSIONS 控制 Agent 与角色组合，_inject_security 覆盖敏感 ID 参数。

数据层

MySQL + ChromaDB + Redis + 本地日志

MySQL 存业务数据、会话、消息、trace、任务、草稿、评估结果与画像；ChromaDB 存向量知识库；Redis 做限流和异步任务事件缓存；logs/ 承载应用日志。

核心模块与知识点

Prompt 设计

四个 Agent 各有系统提示，并拼接安全规则、handoff 规则、运行上下文、用户画像和 RAG 片段。Tutor 强调苏格拉底式提示，Analytics 要求先查真实数据，Generator 输出结构化题目 JSON。

Tool Calling

工具由 LangChain @tool 暴露，LLM 通过 bind_tools 选择工具。执行前检查 agent_type + tool + user_role 权限，执行失败会重试一次并把错误作为 ToolMessage 回传。

RAG 知识库

当前不是全局 retrieve-then-answer，而是在 Tutor 和 Generator 的 Prompt 构造阶段按需检索。Tutor 查知识点和错误模式，Generator 查相似题防重复，生成 pipeline 也会做 dedup 检查。

Memory / State

AgentState 是单次运行状态；AIConversation 与 AIMessage 是对话记忆；StudentProfile 与 TeacherPreference 是跨会话画像。长历史会被 MemoryService.compact_messages 压缩。

日志追踪

TraceCollector 包裹 LLM 和 tool 步骤，记录延迟、token、工具名、输入、成功状态和错误。API 提供 trace 列表与详情，前端有 /ai/traces 页面。

测试评估

单元测试覆盖 Agent、AI API、知识库；E2E 用 Cypress；LLM 行为评估用 evals/runner.py 和 JSON case suite，运行结果可落到 eval_runs。

数据层：Agent 数据存放位置

数据 存放位置 用途
会话 ai_conversations 记录用户、Agent 类型、上下文对象、标题、摘要、创建更新时间。
消息 ai_messages 保存 user/assistant 内容、工具调用 JSON、token 使用量。
运行追踪 agent_runs、agent_run_steps 保存每次 Agent 运行及 LLM/tool 步骤，用于可观测性和排障。
异步任务 agent_tasks + Redis event stream 批量生成、异步 chat、任务状态、重试、结果和错误信息。

学习记忆 student_profiles、teacher_preferences 存学生错误模式、知识图谱、最近题目、教师偏好、班级薄弱点。
RAG 向量库 data/knowledge_base ChromaDB 持久化题目向量、知识点和错误模式。

API 层：如何调用 Agent

接口 调用方式 说明
POST /api/v1/ai/chat 同步 JSON 通用聊天入口，支持 agent_type、conversation_id 和上下文。
POST /api/v1/ai/chat/stream SSE 流式返回 start/token/tool_call/tool_result/handoff/done 等事件。
POST /api/v1/ai/chat/async 任务 ID + 后续轮询/流 创建后台 AgentTask，用于长任务或异步聊天。
POST /api/v1/ai/review 同步 JSON 代码审查专用入口，底层调用 ReviewerAgent。
POST /api/v1/ai/generate 同步 JSON 教师出题入口，底层调用 GeneratorAgent 并保存草稿。
POST /api/v1/ai/generate/pipeline 同步 JSON LangGraph 生成流水线：generate、validate、dedup、quality review、finalize。
GET /api/v1/ai/traces 分页列表 教师/管理员查看 Agent 运行记录。
POST /api/v1/ai/evals/run 同步 JSON 运行指定 eval suite 或全部 suite，并写入历史。

部署、配置、权限与简历价值

Deployment 部署运行

默认通过 docker compose up -d --build 启动 Web、MySQL、Redis。Web 服务由 gunicorn 运行在容器 9900 端口，宿主端口由 WEB_PORT 控制，健康检查访问 /health。

Config 配置管理

核心配置来自 .env、compose.yaml、app/core/config.py 和 app/agents/config.py。关键项包括 DATABASE_URL、DEEPSEEK_API_KEY、AI_MODEL、REDIS_URL、AI_MAX_TOKENS、AI_TEMPERATURE。

Auth 权限认证

API 通过 require_auth、require_teacher 等装饰器保护，认证源包括 Flask session、Authorization Bearer token 和 auth_token cookie。工具层还有 TOOL_PERMISSIONS，生成题目和知识库管理主要限制给 teacher/admin。

Frontend 前端界面

前端是 Jinja 模板、CSS 和 Vanilla JS。主要页面包括 /ai/chat、/ai/review-queue、/ai/traces、/teacher/knowledge，聊天页支持 SSE 流式输出和工具事件展示。

相比普通 Chatbot

普通 Chatbot 多数只有“消息进、模型答”。本项目加入了业务数据库查询、代码沙箱、知识库检索、多 Agent 路由、教师审核流、Trace 可观测性、Eval 评估和角色权限控制。
