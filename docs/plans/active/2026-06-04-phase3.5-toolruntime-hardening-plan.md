# Phase 3.5: ToolRuntime Hardening Plan

> 状态：Active
> 日期：2026-06-04
> 范围：`tools/protocol/runtime.py`、`tools/protocol/schemas/catalog.py`、`tools/protocol/schemas/descriptors.py`

**Goal:** Close the enterprise-grade gaps deferred from Phase 3 that are *boundary-internal* — i.e. they harden the single policy core (`ToolRuntime`) without changing the boundary topology. Phase 3 proved both tool paths share one policy core; Phase 3.5 makes that core production-grade: declared-but-unused reliability fields become real, and the output contract becomes enforceable.

**Architecture:** Every change lands inside `ToolRuntime.call()` and the descriptor catalog. No agent, gateway, client, or transport topology changes. Each task is additive and pinned by tests; the only behavior-affecting flip (output-schema enforce) is gated behind an env toggle defaulting to today's warn-only behavior.

**Tech Stack:** Python 3, `tools.protocol` (`ToolRuntime`, `ToolDescriptor`, `RetryPolicy`), jsonschema, pytest.

---

## Scope decisions (read before starting)

The Phase 3 closeout listed six deferred items. They are not equal — scope is narrowed to the ones that harden the existing core without inventing new subsystems or dead code.

**In scope:**
- **Task 1 — Consume `retry_policy` in the runtime.** `RetryPolicy` (`max_attempts`, `backoff_ms`) is declared on every descriptor ([descriptors.py:22](../../tools/protocol/schemas/descriptors.py)) but `ToolRuntime.call()` never reads it — a declared-but-dead field. Wire bounded retry on *retryable* errors only (`RATE_LIMITED`, `TRANSPORT_UNAVAILABLE`, `TOOL_TIMEOUT`; see `_RETRYABLE` in [errors.py:35](../../tools/protocol/errors.py)). **Zero live behavior change**: every current descriptor has `max_attempts=0`, so all tools still make exactly one attempt. This only makes the mechanism real for future tools.
- **Task 2 — Complete real `output_schema`s + an enforce toggle.** 11 of 15 catalog tools carry the placeholder `output_schema={"type": "object"}` ([catalog.py](../../tools/protocol/schemas/catalog.py)). Write real schemas, then add `MCP_OUTPUT_SCHEMA_ENFORCE` (default off = today's warn-only, [runtime.py:229](../../tools/protocol/runtime.py)). Flipping to enforce becomes a one-env-var decision once schemas are trusted, instead of a code change. Keeps "先松后紧" but makes "紧" reachable.

**Out of scope (with rationale):**
- **Multi-tenant isolation (`CallerContext.tenant_id`).** Zero consumers anywhere in the repo; the platform is single-tenant today. Building guard enforcement now creates dead code for a requirement that does not exist — textbook YAGNI. Revisit only when a real multi-tenant requirement lands.
- **Per-tool / per-user quotas.** Needs a Redis-backed counter store and an ops policy; this is operational quality-gate territory → **Phase 6**, not boundary hardening.
- **Write-tool idempotency keys.** The only write tool (`save_generated`) is already approval-gated through the approval store. Low urgency; defer until a second write tool exists.
- **Live-HTTP streamable-http integration test.** Token mint/verify and gateway caller resolution are already unit-tested; a booted-server E2E belongs with the Phase 6 eval/CI harness.

## Constraints (do not violate)

- `ToolRuntime` public API (`call`, `call_sync`, `list_tools`) and the envelope shape MUST be unchanged.
- Retry MUST only fire on `MCPErrorCode.retryable` errors and MUST respect `max_attempts` (0 → exactly one attempt). Generic exceptions become non-retryable `MCPInternalError` and MUST NOT be retried.
- Retry MUST wrap only the transport execution — not guard, input validation, or output validation (a schema mismatch is not a transient fault).
- The output-schema enforce toggle MUST default to **off** (warn-only), so completing schemas cannot turn a previously-working tool into an `MCPSchemaInvalid` error without an explicit ops decision.
- Existing suites MUST stay green: `tests/test_tool_protocol.py`, `tests/test_mcp_boundary_consistency.py`, `tests/test_mcp_gateway_*`.

## Acceptance Criteria

- [ ] `retry_policy` is honored: a tool with `max_attempts>0` retries retryable failures and stops at the ceiling; `max_attempts=0` tools are unchanged.
- [ ] Output-schema enforcement is a single env toggle; default behavior is byte-for-byte today's warn-only.
- [ ] No catalog tool carries a placeholder output schema.

## Out of scope (tracked for Phase 6)

Multi-tenant isolation (dropped as YAGNI), per-tool/per-user quotas, write-tool idempotency, live-HTTP integration test.
